# 01-00 Sync Original Updates - 需求

## L0 摘要

同步 `gemini-web2api-oran` 原始项目的新功能到当前管理版项目，保留本地管理增强能力。

## L1 概览

### 目标

对比当前仓库与 `gemini-web2api-oran/gemini-web2api-main` 原始项目源码，将上游新增或修复的功能合并到当前分支，同时避免覆盖当前项目已有的管理后台、日志和配置增强。

### 用户故事

- 作为维护者，我希望当前管理版跟进原始项目更新，以便继续获得上游功能和修复。
- 作为使用者，我希望同步后原有管理后台功能仍可用，以便不因上游同步破坏现有工作流。

### 范围

**包含**：
- 对比原始项目目录与当前项目源码差异。
- 合并与运行时 API、配置、脚本、文档相关的上游更新。
- 处理合并冲突并保留当前管理版已有能力。
- 做最小可行验证，确认核心 Python 模块可导入或编译通过。

**不包含**：
- 不重写整体架构。
- 不主动删除本地管理后台功能。
- 不提交 Git commit 或推送远端。

## L2 详情

### 详细需求

#### F-01 上游差异识别
- 描述：识别原始项目相对当前项目的新增、删除和修改文件，并区分上游功能变化与当前管理版定制。
- 验收：WHEN 完成对比 THEN 能列出同步范围和保留的本地定制。

#### F-02 功能同步
- 描述：将原始项目的新功能和修复合并到当前项目对应模块。
- 验收：WHEN 上游修改与本地增强冲突 THEN 优先保留本地管理能力并吸收上游修复。

#### F-03 基础验证
- 描述：对同步后的 Python 源码执行可用的静态或导入级验证。
- 验收：WHEN 验证命令执行 THEN 不出现由本次同步引入的语法错误。

### 非功能性需求

- 性能：不引入明显额外启动开销或请求链路阻塞。
- 兼容性：保留当前 Python 项目结构、配置文件格式和已有管理页面入口。

### 边界与依赖

依赖本地已解压的 `gemini-web2api-oran/gemini-web2api-main` 原始项目目录；不依赖远端网络拉取。

### 验收标准

- [x] 原始项目新增/修改的核心功能已评估并同步。
- [x] 当前管理版已有后台、日志和配置增强未被整体覆盖。
- [x] 私有反代域名可通过管理页或 `GEMINI_BASE_URL` 配置，默认仍使用官方域名。
- [x] Python 源码通过最小语法验证。
