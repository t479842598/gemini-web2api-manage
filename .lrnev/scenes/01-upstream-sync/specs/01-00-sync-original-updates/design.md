# 01-00 Sync Original Updates - 设计

## L0 摘要

采用目录差异对比加选择性合并方式，同步原始项目更新并保留当前管理版定制。

## L1 概览

### 架构思路

先以原始项目目录作为上游快照，对比同名文件内容；对运行时核心模块逐文件合并，对管理版专属文件默认保留。同步时优先处理源代码和配置示例，再处理文档与构建文件。

### 主要模块

- `gemini_web2api.py`：单文件运行入口与核心 API 行为。
- `gemini_web2api/`：包化运行模块。
- `web-admin/`、`manager.pyw`：当前管理版本地增强，默认不被上游覆盖。
- `README*.md`、`config.example.json`、`pyproject.toml`：同步说明与配置契约。
- `gemini_base_url`：可选私有反代请求目标，留空默认 `https://gemini.google.com`。

### 关键决策

| 决策 | 选项 | 倾向 | 是否产 ADR |
| --- | --- | --- | --- |
| 同步方式 | 全量覆盖 / 选择性合并 | 选择性合并 | 否 |
| 本地增强 | 跟随上游删除 / 默认保留 | 默认保留 | 否 |

## L2 详情

### 模块详细设计

1. 使用递归文件哈希或文本 diff 识别原始项目和当前项目的差异。
2. 对同名核心源码逐段合并，避免覆盖当前分支已有流式响应、管理日志和后台入口修复。
3. 对上游新增文件按用途决定是否复制到当前项目。
4. 对文档和配置示例进行最小同步，保持当前项目说明真实。

### 数据模型

不新增持久化数据模型；沿用当前配置文件和运行时状态结构。

### 接口契约

保持现有 Web API 路由、配置文件键名和管理后台入口兼容；仅吸收上游新增兼容行为。

### 错误处理

冲突文件先人工审查再修改；验证失败时只修复由同步引入的问题，不扩大到无关缺陷。

### 测试策略

优先执行 Python 语法编译检查；如果项目提供轻量测试或启动检查，再运行对应命令。
